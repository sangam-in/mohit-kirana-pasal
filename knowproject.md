# 📱 Hamro Kirana Management - Project Guide

## 🎯 What is This Project?

**Hamro Kirana Management** (also called **Kirana Sahayog**) is a web-based **POS (Point of Sale) billing and ledger (Khata) application** designed specifically for small neighborhood Kirana stores in Nepal.

**In simple terms**: It's a cash register and account book in one app. Store owners use it to:
- Process customer payments (bills/invoices)
- Track inventory (products and stock levels)
- Maintain customer credit accounts (Khata - the traditional ledger system in Nepal)
- Generate sales reports

---

## ✨ Key Features

### 1. **POS Billing System**
   - Create and process sales transactions
   - Accept multiple payment methods: Cash, QR Payment, Khata (credit)
   - Real-time bill printing/display
   - Track sales history

### 2. **Inventory Management**
   - Add and manage products with prices
   - Track stock levels (pack and loose units)
   - Low stock alerts
   - Support for Nepali product names and emoji icons

### 3. **Khata (Credit Ledger)**
   - Maintain customer credit accounts
   - Track debit/credit entries
   - View customer balance and transaction history
   - Know which customers owe money and how much

### 4. **Customer Management**
   - Store customer information (name, phone)
   - Track customer balance
   - See last activity date
   - Organize customers with avatar colors

### 5. **Smart Audio Feedback**
   - POS beep sound for all transactions
   - Special Nepali voice confirmation for QR payments: "भुक्तानी भएको छ" (Payment done)
   - Toggle between female/male voice in settings
   - Enhances user experience with native language feedback

### 6. **Reports & Analytics**
   - View sales trends
   - Generate transaction reports
   - Customer transaction history
   - Inventory status reports

## 🔄 How the App Works (Workflow)

### User Registration & Login Flow
1. User visits the app
2. Clicks "Sign Up" and creates account with email + password
3. Supabase authenticates the user and creates account
4. User is redirected to Dashboard
5. All data is now isolated to this user only (for security)

### Making a Sale (POS)
1. Store owner goes to **POS** page
2. Scans product barcode or searches for product
3. Selects quantity
4. Adds to cart/bill
5. Selects payment method:
   - **Cash**: Payment complete immediately
   - **QR**: Triggers Nepali voice confirmation + beep
   - **Khata**: Adds to customer's credit account
6. Transaction is saved to database
7. Bill is displayed/printed

### Managing Customer Credit (Khata)
1. Go to **Khata** page
2. Select a customer
3. View their balance and transaction history
4. Add new credit/debit entries
5. Track when customer pays back
6. See outstanding amounts

### Checking Inventory
1. Go to **Inventory** page
2. View all products with current stock levels
3. See products running low (below threshold)
4. Add new products or edit existing ones
5. Updates reflected in real-time across POS

### Viewing Reports
1. Go to **Reports** page
2. See sales trends and analytics
3. Export transaction data if needed
4. Analyze customer payment patterns

## 🎨 Design System

The app uses a **warm, premium bento-card design**:

### Color Palette (Warm Cream Theme)
- **Background**: Soft cream/beige
- **Cards**: Light tan with rounded borders (`rounded-[2rem]`, `rounded-3xl`)
- **Borders**: Subtle warm grays
- **Text**: Warm browns and blacks

### Typography
- **Headings**: Space Grotesk (bold, clean)
- **Body Text**: DM Sans (readable, friendly)
- **Large Displays**: `font-display` class for titles

### Currency Formatting
- All prices formatted as **Nepali Rupees**: `रु 500`, `रु 1,250`
- Use `formatNPR()` function from `store-data.ts`

### Component Philosophy
- Heavy use of rounded corners for warm feeling
- Soft shadows instead of harsh borders
- Ample padding for breathing room
- Consistent spacing throughout

## 🔐 Security & Data Isolation

### Row-Level Security (RLS)
- Each user's data is **100% isolated** using Supabase Row-Level Security
- The database automatically checks: Is this data owned by the logged-in user?
- Users cannot access other users' data, even if they try to hack the URL

### What's Isolated?
- Products (inventory)
- Customers (accounts)
- Sales (transactions)
- Khata entries (ledger)
- All financial records

### How It Works
```sql
-- Example: Only show products owned by the logged-in user
WHERE user_id = auth.uid()  -- Supabase automatically replaces with current user's ID
```

## 🎵 Special Feature: Nepali Voice Confirmation

### Payment Sound System

**For All Payments:**
- Plays a classic **POS double beep** sound (ding-ding)

**For QR Payments Only:**
- Also plays a **Nepali voice recording** saying: "भुक्तानी भएको छ" (Bhuktani bhayeko chha)
- This means: "Payment has been done/received"

### Voice Options
- **Female voice** (default): `/payment-success-ne-female.mp3`
- **Male voice**: `/payment-success-ne.mp3`

### User Settings
- Store owner can toggle between voices in **Settings** page
- Preference saved to browser's `localStorage`
- Can be toggled anytime without page reload

### Why This Feature?
- Makes payment confirmation feel authentic to Nepali stores
- Helps both staff and customers recognize payment completion
- Improves user experience with native language feedback

## 📝 Development Guidelines

### When Adding New Features

#### 1. **Creating New Pages/Routes**
- Add a new `.tsx` file in `src/routes/`
- TanStack Router auto-generates routing
- Protected routes go in `src/routes/_authenticated/`

#### 2. **Database Queries**
- All Supabase queries go in `src/lib/store-data.ts`
- Use React Query hooks (`useQuery`, `useMutation`)
- Automatic real-time updates when data changes

#### 3. **UI Components**
- Use existing Radix UI components from `src/components/ui/`
- Follow the warm design system
- Keep rounded corners and soft styling

#### 4. **Styling**
- Use Tailwind CSS classes
- Follow design system colors: `bg-card`, `border-border`, `text-muted-foreground`
- Use display font for titles: `font-display text-3xl`

### Git Workflow
⚠️ **IMPORTANT**: Do NOT rewrite published git history
- No force pushing (`git push -f`)
- No squashing or amending already-pushed commits
- The project syncs with Lovable platform - history is critical

### File Organization Best Practices
```
✅ DO:
- Keep related logic together (database queries in store-data.ts)
- Name components descriptively (CustomerSelector, SalesChart)
- Use TypeScript interfaces for data types
- Comment complex logic

❌ DON'T:
- Scatter Supabase queries across multiple files
- Create inline styles (use Tailwind classes)
- Rewrite git history
- Mix business logic with UI components
```

## 🚨 Common Issues & Solutions

### "Page not found" error
- Make sure you're in an authenticated route after logging in
- Check if route file exists in `src/routes/`

### Database queries not working
- Check Supabase authentication status
- Verify RLS policies allow your user access
- Check browser console for error messages

### Audio not playing
- Check if browser allows audio playback
- Verify audio files exist in `/public/`
- Check browser console for audio errors

### Styling looks broken
- Make sure Tailwind CSS is loaded (`src/styles.css`)
- Check if class names match Tailwind syntax
- Clear browser cache and restart dev server
